# Quality-upgrade implementation path audit

Status: P0 read-only code audit complete, 2026-10-23. Baseline: `main` at `161b558`, isolated branch `codex/quality-upgrade-20261023`. Line references below describe that baseline; later implementation can move them.

Scope: native quality settings -> saved request/job -> worker -> canonical 3DGS/2DGS -> CUDA -> checkpoint/RNG -> export/viewer. No training, GUI launch, native build, original-data modification, runtime installation, commit or push in this audit.

## Initial findings

- Existing quality presets primarily select iterations and resolution; training runtime/performance policy is independently versioned. New quality mechanisms must not rewrite those unrelated fields.
- `canonical_training._camera_from_view` currently passes `depth_params=None, invdepthmap=None` for 3DGS and `gt_alpha_mask=None` for 2DGS. The canonical path therefore does not currently deliver user depth/mask supervision, although upstream noncanonical loaders and losses have partial mechanisms.
- Full checkpoints already capture Gaussian optimizer/densification state, Python/NumPy/Torch/CUDA global RNG state and pending camera indices. This is a reuse seam, not yet proof of independent initialization/sampler/method-noise RNG streams. No `batch_pending_names` field exists in the audited path.
- Shared planning is root-owned at `.planning/2026-10-23-quality-upgrade-20261023`; this worker owns only this ledger.

### Depth/mask details and safe reuse seams

- `native/backend/camera_dataset.py:417` preserves extra view keys via `dict(value, ...)`, but it has no decode/geometry/confidence validation for mask/depth. Merely placing filenames or metadata in a view currently does not create supervision.
- `canonical_training._camera_from_view` (`:360`) is the narrow shared camera seam. Preserve its full-K projection, clipping, view identity and fixed-camera optimizer assertion; inject only validated training-view payloads.
- `native/worker/training_image_pipeline.py:44` (`HostCameraImage`) and `:241` (`ReadyImage`) already carry RGB, alpha, inverse depth and depth mask through bounded host/pinned/GPU transfer. Extend deliberately for confidence and semantics; do not bypass staging/resource lifetime policy.
- The upstream camera uses `cv2.resize`, clamps negative depth to zero and initializes an all-ones depth mask. That is not sufficient to validate NaN/Inf, missing confidence, ray-range reprojection or sensor coordinate changes.
- `native/worker/training_loss.py:48` `PhotometricLoss.compute(image,target,weight)` only supports the L1/SSIM blend; it has no per-pixel supervision-weight or alpha-negative interface. It is shared by both trainers, so weighted-mask semantics need a separate explicit module or compatible shared extension with fused-loss compatibility gates.
- Existing inverse-depth loss uses `(abs((prediction-target)*depth_mask)).mean()`, i.e. a whole-image denominator, not valid-weight normalization. New behavior must be opt-in; Standard must retain its baseline operation order.
- `native/worker/surfel_regularization.py:6` keeps native 2DGS normal/distortion terms backend-appropriate and separate from photo loss. Preserve them; do not relabel internal regularization as externally sourced depth supervision.

## RNG and checkpoint audit

1. **Initialization is already independently generated.** `native/backend/initialization.py:266` uses its own `np.random.RandomState(declaration['seed'])` and persists actual float64 points/point hash. Retain this behavior and identity.
2. **Training seed currently seeds globals.** `training_seed.py:25-41` seeds global Python, NumPy and Torch. Default zero intentionally matches upstream. It explicitly does not guarantee bitwise GPU reproducibility.
3. **Sampler is global Python RNG.** Both `train.py:224` and `two_dgs_train.py:171` use imported `random.randint`, removing cameras without replacement until refilling. Native trainers sort camera lists first (`train.py:130-135`, `two_dgs_train.py:117-120`) so saved indices remain meaningful. Canonical `audit_sample` already appends actual `(iteration,view_id)` JSONL.
4. **Method noise is not independently scoped.** Existing split uses global Torch RNG and random background uses global CUDA Torch RNG (`train.py:234`). Future method noise using Python globals would perturb sampler order; extra Torch noise can perturb Standard split/background. Independent stream objects/state and sequence tests are missing. A new isolated sampler must also preserve legacy Standard/off sequence or explicitly version the migration; identical seed labels alone are not invariance.
5. **Complete pause state is reusable.** `training_checkpoint.py:98-121` captures Gaussian optimizer/densification state, 3DGS exposure+optimizer+mapping, all global RNGs, camera names, pending indices, seed and camera contract. `:124-148` validates identity, backend, total schedule, seed, camera contract and pending indices before optimizer/RNG restore. Trainers append `density_control`; runtime adds renderer engine, runtime policy/history, growth and execution-quality profile (`training_runtime.py:457`).
6. **Native saves are iteration-boundary transactions.** 3DGS `train.py:407-423` and 2DGS `two_dgs_train.py:287-303` save after density updates and optimizer step, resuming at `iteration+1`. `TrainingCheckpoint.save` (`training_checkpoint.py:167`) publishes hash-checked payload then `ready.json` last and only then removes previous state. Load (`:211`) checks manifest identity before trusted pickle deserialize.
7. **Scheduled checkpoint files are not complete native state.** `compute.py:5062` and `:5135` schedule PLY/legacy checkpoint milestones; trainers write `(gaussians.capture(),iteration)` to `chkpnt*.pth` (`train.py:398`, `two_dgs_train.py:282`). Those files omit sampler/RNG/exposure/runtime/plan state. The complete `.gsw-resume` is presently only saved on explicit/resource pause, not every requested 3k/7k/15k milestone. Q02/Q12 therefore require an explicitly complete scheduled-state path, not relabeling these legacy files.
8. **Identity coverage is partial for new quality.** `training_checkpoint.training_identity` (`:65`) hashes effective dataset/opt/pipe, selected input bytes, density source and canonical/initialization source; canonical contract records actual rasterizer/wrapper/runtime identity (`canonical_training.py:445`). It has no quality-plan hash, method-buffer version or supervision source contract yet. 2DGS additionally fingerprints actual external source files (`two_dgs_train.py:107-112`). Reuse and extend, do not discard existing checks.

## Renderer, export and viewer constraints

- 3DGS render seam: `gaussian-splatting/gaussian_renderer/__init__.py:18` creates retained screen-space points and returns render/radii/inverse depth, choosing raw model opacity/scales/rotation or precomputed covariance. The Python/CUDA wrapper ABI in `submodules/diff-gaussian-rasterization/diff_gaussian_rasterization/__init__.py:44` currently returns only color/radii/inverse depth; there are no AbsGS/Pixel/filter result fields. CUDA aux-buffer changes require explicit ABI version and checked runtime proof.
- `NativeTrainingRuntime.select_renderer` (`training_runtime.py:520`) already checks resume engine compatibility. `training_acceleration.select_acceleration` (`:21`) rejects fastergs use for surfels, depth, required radii, precomputed covariance etc by returning an explicit stock decision for *performance selection*. A quality resolver must not mistake that performance fallback as permission to replace requested algorithms with Standard. Canonical supervision must also update `requires_depth`: today it is derived only from `dataset.depths` (`training_runtime.py:539`).
- `CanonicalScene.save` (`canonical_training.py:530`) writes the raw backend PLY and camera-scale sidecar with file hash; native delivery (`gsw_worker.py:1056` onward, `camera_scale_export.py:1058`) keeps raw model/checkpoint and creates a distinct delivery derivative.
- `native/backend/camera_scale_export.py:744` requires new outputs and supports full typed Gaussian attributes, SH rotation, 2D/3D scale dimensions, optional deleted indices, camera/scale provenance and transactional bundle publication. This is a strong reuse seam for source-preserving cleanup/fused exports, but it currently has no filter-state semantics.
- Native PLY loader (`native/src/PlyPointCloudLoader.cpp:2174`) maps standard opacity/scale/rotation/SH fields into viewer data. Unknown numeric properties can be parsed without affecting the rendered Gaussian attributes. Thus adding raw filter fields alone would not render Full Mip correctly or explicitly reject it.
- Native 3DGS viewer shader (`native/src/NativeViewport.cpp:2873-2925`) computes covariance from scale/rotation, adds **0.09** screen covariance and clamps sigma. It does not apply the training renderer's **0.3** screen covariance and determinant-ratio AA opacity compensation, nor a 3D filter. This is a pre-existing parity limitation, not proof that a new fused export is visually equivalent. Record it and use same-camera evidence for QT016/QT017 before any Full-Mip support claim; do not expand this audit into an unrelated renderer rewrite.
- Native 2DGS has a dedicated plane-ray/surfel branch in the same shader (`NativeViewport.cpp:2845` onward), not a 3D ellipse alias. Preserve it; `generation_capabilities.py` already describes center-sorted OpenGL versus upstream tile-renderer limitations.

- Existing `gs_geometry` is explicitly opacity-rendered depth as an appearance proxy, not physical/material geometry ground truth (`native/worker/generation_capabilities.py:73`). Never route its outputs silently into depth supervision/evaluation or label geometry accuracy measured.

## Small-module implementation seams (recommendations, not implemented here)

1. Resolve a JSON-only quality request once with explicit backend/kernel capabilities, effective values, reason codes, versions and semantic hash. Callers and tests cross that same interface at saved request/job/CLI/resume. Keep existing preset/runtime/camera inputs outside its mutation scope.
2. Attach a densification adapter at existing trainer stat-consumption and native density-guard seams; keep Standard adapter byte/operation-order compatible. AbsGS/Pixel require actual renderer statistics; MCMC requires its own transition/state adapter rather than hooks that merely rename Standard.
3. Attach validated supervision at canonical view->camera and shared ready-image/loss seams, with train-only split checks and preserved coordinate transformations. Make missing/invalid supervision explicit before renderer admission.
4. Place sampling/filter state behind the model/render/export seam with one raw/active/fused meaning and no implicit double application. Native viewer either consumes the same state or loads a clearly fused derivative.
5. Extend existing capture/restore, immutable source/binary identity, transactional outputs, evaluator and serial benchmark descriptions. Do not add a parallel giant plugin/config framework.

## Backend capability discipline

`native/worker/generation_capabilities.py` is the existing release matrix for 3DGS, 2DGS, bounded/unbounded TSDF, SuGaR, GS2Mesh and OpenMVS. Only 3DGS/2DGS own the Gaussian training optimizer/checkpoint path. Downstream mesh/refinement methods have distinct limitations, no optimizer resume adapter, and reject canonical-camera inputs pending their own camera/depth/split integration. New shared quality-plan storage/identity/monitoring should remain coherent across 3DGS/2DGS. Do not claim every downstream mesh pipeline supports the new quality algorithms merely because its source PLY can be generated. Required follow-up: method-specific capability rows with technical unavailable reasons and real acceptance gates, plus all user-facing reasons/status in zh_CN/en_US/ja_JP with live `AppLanguage` updates.
